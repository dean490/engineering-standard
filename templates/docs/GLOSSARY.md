# Glossary

The words this project uses for its own concepts (STANDARD 8.5). Specs, briefs, tests, and code use these words and not the ones under *Avoid*. Add a term the moment an interview (STANDARD 1.8) settles it. Format after `domain-modeling` in `mattpocock/skills` (DECISIONS 19).

Rules:

- Be opinionated: when several words exist for one concept, pick one and list the others under *Avoid*.
- Define what a thing is, in one or two sentences, not what it does.
- Only terms specific to this project. General programming concepts (timeout, retry, utility) do not belong here.
- Nothing about implementation: this file is not a spec, a scratch pad, or a place for decisions (those go in `docs/DECISIONS.md`).
- Group terms under subheadings only when clusters emerge.
