## 0.1.0 (unreleased)

First version.

- `CONSTITUTION.md` v0.1 and `STANDARD.md` v0.1, whose rules are tagged [enforced] (a wall), [guarded] (a hook or permission rule, with its wall named), [checked], or [practice].
- `templates/`: `AGENTS.md`, `CLAUDE.md`, `.claude/settings.json` (deny, ask, and allow rules; sandbox, with a network allowlist that leaves out GitHub, read and write blocks on `.env*` at any depth, write blocks on `.github/`, `.githooks/`, and the gitleaks files, and token variables removed; the Supabase CLI's local-stack commands outside the sandbox by absolute path; this repository, `dean490/engineering-standard`, as the plugin marketplace), `.claude/rules/` for migrations, row-level security, and tests, `pnpm-workspace.yaml` supply-chain settings, `tsconfig.base.json`, `.githooks/pre-commit` (a gitleaks scan of the staged changes with the built-in rules, which fails closed without gitleaks), the CI workflows (`ci.yml` and `guards.yml`), the CI check scripts in `scripts/`, Dependabot, the pull request template, the `docs/` skeleton, and `.gitignore`.
- `plugin/` (`eng-standard` 0.1.0): hooks `secret-guard-read`, `secret-redact`, `protect-paths`, `commit-hygiene`, `planner-readonly`, `critic-readonly`, and `stop-gate`; agents `critic` and `security-reviewer`; skills `gate`, `handoff`, and `critic-pass`; tests on Node's built-in test runner.
  - `planner-readonly` records each session's role from its first prompt: a session that starts in plan mode is a Planner session for its whole life, whose file edits in the repository are denied and whose shell commands must be read-only; any other session is a Builder session, which plan mode alone governs.
  - `commit-hygiene` blocks, besides bulk staging, `git commit -m`, force pushes, and remote database changes, every Vercel deploy and promotion (deploys happen through GitHub), commands that destroy uncommitted work, and every way it can see to skip git hooks, including through `npx`, `pnpm exec` and `dlx`, `bunx`, and `yarn`.
  - `stop-gate` runs nothing: it asks a Builder session to run `/eng-standard:gate fast` when it would stop with uncommitted changes and no passing gate record for them.
- `.claude-plugin/marketplace.json`: this repository is a plugin marketplace named `engineering-standard`.
- `docs/ADOPTING.md`, including the `prepare` and `gate:fast` scripts a project adds to `package.json`, installing gitleaks, and the `docs/DEVIATIONS.md` entry for a private repository without GitHub push protection.
- `DECISIONS.md`: entries 1 to 15.

### Changes from the Critic pass (2026-10-08, `.recon/critic-v0.1.0/REPORT.md`, brief 03)

- Guardrails and walls (DECISIONS 11): the [guarded] tag; each rule re-tagged by what holds it; STANDARD 3.8, production credentials stay off development machines; STANDARD 1.1, a Planner session is never forked to build.
- `stop-gate` no longer runs project scripts (CR-1, CR-14). The `gate` skill, which Claude can now invoke, runs `gate:fast` (`/eng-standard:gate fast`) or `gate` in the sandbox and records the result with a fingerprint of the uncommitted changes in `.recon/gate/last.json`; the hook blocks a Builder's stop once when no passing record matches. DECISIONS 10 replaced.
- Supabase (CR-2, CR-9): only `--local` forms of `db reset`, `db diff`, `test db`, and `gen types` run outside the sandbox; `commit-hygiene` blocks `--linked`, `--db-url`, and `--project-ref` in any spelling, remote `--from`/`--to`, and the commands that change a remote project; development machines don't link to staging or production.
- Monitor (CR-3): every hook that reads shell commands also runs for the Monitor tool, and a test pins every hook's matcher.
- `commit-hygiene` (CR-4, CR-5, CR-8, CR-13): abbreviated long options, `-c alias.*` and includes, `GIT_CONFIG*`, `HOME`, and `XDG_CONFIG_HOME` overrides, git run through a variable, substitution, `eval`, `xargs`, or `find -exec`, plumbing (`read-tree -u`, `commit-tree`, `update-ref`, `symbolic-ref` writes, `checkout-index -a -f`), aliases from the user's config, `GITLEAKS_*` variables, `git add --pathspec-from-file`, and commit pathspecs that cover more than one file; `-S` takes only an attached value; a pathspec that names an existing file, or uses `:(literal)`, counts as a name, so Next.js route files such as `app/[slug]/page.tsx` can be staged and restored.
- `protect-paths` (CR-5, CR-21): `.githooks/`, all of `.github/`, `.gitleaks.toml`, `.gitleaksignore`, and the CI check scripts.
- Read-only sessions (CR-7, CR-10, CR-11): the Planner guard applies the Critic's shell allowlist (shared in `hooks/lib/readonly-allowlist.cjs`) to Planner sessions, treats an unreadable role record as a Planner, and keeps every session's file tools out of the plugin's data directory; the allowlist catches abbreviated and clustered git options, `sort -o`, snapshot updates, and `tsc` without `--noEmit`.
- `secret-redact` (CR-12, CR-15): a `BEGIN ... PRIVATE KEY` line counts without its END line; the local Supabase stack's fixed demo keys are exempt. `secret-guard-read` (CR-16) reads commands with the shell parser, so jq paths and grep patterns are no longer taken for files, and a glob that matches a secret file counts.
- CI (CR-6, CR-17, CR-18, CR-19, CR-20, CR-21, CR-22): new jobs **Migrations are append-only**, **Test integrity**, and **Sensitive change**; row-level security and client bundle checks in **Gate**; the pinning check covers local composite actions and requires digests for `docker://`; the secret scan uses gitleaks's built-in rules only.
- Sandbox (CR-23): explicit `denyRead` entries for `.env*` at any depth, checked with the macOS sandbox; the check inside a live session is a required adoption item.
- Tests: 57 to 92 hook tests, plus 6 tests of the CI check scripts (`tests/`).

### `.git` write surface (2026-10-09, briefs 06 and 07)

- `templates/.claude/settings.json` and `.claude/settings.json`: the `Edit` deny rules stay `Edit(/.git/config)`, `Edit(/.git/config.worktree)`, and `Edit(/.git/hooks/**)`. Brief 06 widened them to `Edit(/.git)` and `Edit(/.git/**)` and that broke `git add` (`Unable to create '.git/index.lock': Operation not permitted`), so the widening is withdrawn. `Edit(/.git)` on its own was not probed (`.recon/brief-07/git-entry-probe.txt`) and is not in the rule set.
- Why the rule stops there is recorded in DECISIONS 12: `Read` and `Edit` deny rules are merged into the sandbox write block, so a rule over all of `.git` makes `.git/index.lock` unwritable to every sandboxed command. The three paths are ones git never writes during ordinary work. Uncovered, and named there: `.git/modules/**` configs and hooks, `.git/worktrees/**/config.worktree`, and the worktree pointer file. The primary-working-directory anchor limit in STANDARD 3.5 and DECISIONS 12 is unchanged.
- ADOPTING: a required live check that Claude's Edit tool can't write `.git/config` and its Write tool can't write `.git/hooks/probe`, with a `git add <a named file>` sub-check that proves the rules didn't take git's own paths with them; not applicable in a worktree session. A "Consequences to know about" bullet tells adopters not to deny a path a tool has to write.
- Test: the brief 04 review test in `tests/template-config.test.cjs` is now the brief 07 test; it asserts the three entries in both settings files and that `Edit(/.git/**)` is absent, with both limits and their doc lines in its comment. Evidence: `.recon/brief-06/git-deny-wide.txt`, `.recon/brief-07/`.
